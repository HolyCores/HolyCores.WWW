01 / OVERVIEW

从找到答案，
到完成任务。

知识问答、固定工作流和自主任务执行，需要不同的系统设计。先确定业务目标，再选择适当的复杂度。

01

知识助手

从资料中检索相关证据，生成带出处的回答；证据不足时说明缺口。

02

业务工作流

以固定步骤连接模型、规则与业务接口，适合重复性强、验收明确的任务。

03

任务型智能体

按目标选择工具、检查结果并调整计划，以权限、预算与停止条件约束执行。

02 / RETRIEVAL AUGMENTED GENERATION

让回答回到证据。

RAG 在生成前检索企业资料，为模型提供相关上下文。数据更新、检索质量与引用准确性，共同决定回答是否可信。

01 →

接入与整理

解析文档与表格，保留来源、版本、更新时间及访问权限。

02 →

索引与更新

按内容结构分块，建立文本与向量索引，同步新增、变更和删除。

03 →

检索与重排

在权限范围内组合关键词与语义检索，通过重排筛选相关证据。

04 →

生成与引用

组织上下文、生成答案并关联原文位置；避免将引用等同于正确性。

05 →

评估与反馈

用代表性问题检查召回、事实支持和引用，持续修正数据与配置。

复杂问题可采用 Agentic RAG：拆分子问题、多轮检索并检查证据覆盖。是否启用，取决于质量收益能否覆盖额外时延与成本。

03 / AGENTIC EXECUTION

让执行形成闭环。

当任务需要动态选择下一步时，由智能体协调检索与工具。对路径明确的流程，优先采用可预测的工作流。

01

目标与计划

拆解任务，明确输入、成功标准、步骤上限和预算。

02

工具与权限

为检索、数据库查询与业务操作设置清晰接口，按用户身份限制可访问范围。

03

状态与恢复

记录任务进度、工具结果与检查点，设计超时、重试、幂等和失败恢复。

04

关键操作确认

对发送、写入与其他高影响操作设置确认点，让用户理解执行对象和影响。

05

结果与验证

依据业务规则检查输出及系统实际状态，失败时重试、回退或转交人员。

06

追踪与评估

关联模型调用、工具事件与任务结果，用测试集检查版本变更的影响。

05 / EVALUATION

用任务结果，
衡量系统价值。

联合评估检索、生成、工具执行与基础设施。把质量、时延和成本放在同一套可复现基线中。

评估维度观察指标验收重点
检索质量Recall@k、排序质量、权限过滤资料是否找全，相关证据是否排在前面。

FAQ

从第一个应用开始。

RAG 能彻底消除幻觉吗？

不能。检索遗漏、资料冲突或模型误读仍可能导致错误，需要证据检查、引用验证以及资料不足时的拒答策略。

RAG 与微调如何选择？

RAG 适合引用私有或经常变化的知识；微调更多用于调整行为、风格或特定任务表现，两者也可以结合。

是否需要一开始就使用多个智能体？

不需要。先验证简单检索或单智能体流程；只有任务确实需要拆分，且收益得到评估支持时，再增加协作复杂度。

可以在企业自有环境验证吗？

可围绕本地数据边界规划验证方案，具体取决于模型许可、目标硬件、软件适配及业务接口。请提供样例资料与部署约束。
