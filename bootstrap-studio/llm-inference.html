MEASURE THE EXPERIENCE

推理速度， 不只是一个峰值数字。

真正的服务体验由提示词处理、首字响应、持续生成、并发容量与稳定性共同决定。我们围绕真实模型、上下文、精度和服务等级建立可复现基线。

TTFT

首字时延

衡量请求进入后，第一个 Token 到达用户所需的时间。

TPOT

持续生成

观察 Decode 阶段相邻 Token 的间隔与交互流畅度。

THROUGHPUT

吞吐与并发

在目标时延约束内，评估系统可稳定承载的请求规模。

EFFICIENCY

单位服务成本

将能耗、容量、利用率和可用性纳入每次推理的系统成本。

PREFILL + DECODE

为不同计算阶段， 安排正确的资源。

FAQ

从真实模型开始。

哪些模型可以部署？+

模型支持需要结合架构、算子、精度与上下文配置验证。建议提交目标模型和服务指标，由双方建立明确的兼容性与性能基线。

应该优先优化 TTFT 还是吞吐？+

取决于业务。交互式助手通常更看重 TTFT 与 TPOT，批处理任务更关注吞吐和单位成本；生产方案应明确优先级和可接受边界。

能否从单卡验证后再扩展？+

可以。先在 NOVA 或 AETHER 单节点验证模型质量和性能，再依据并行策略与网络效率扩展到多节点系统。
